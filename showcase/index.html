Three initiatives. One framework.

Context → Need → Role → System → Evidence → Reuse. If it can't answer all six, it isn't in the showcase.

Context

Need

A way to make improvement visible, repeatable, and provable — without adding another standing meeting.

Role

Designed and operationalized the WCS-wide CI operating model, end to end.

System

DRIPS: Detect → Root cause → Improve → Prove → Share, running on Teams front door → Jira execution → SharePoint proof.

Evidence

Meeting Room Tech audit: target of 100 rooms in the run — 244 completed, with a runbook produced along the way. Sprint 70 fleet baseline: 2,721 managed devices categorized and audited; Windows MTR compliance at 1,417 of 1,505 PASS (94.2%), with DATA-MISSING syncs separated from true FAILs so the number means something.

Screen 04 · Operating systems for work

The DRIPS loop

More than project coordination — this is designing how work moves. Watch the loop run.

D

Detect

Signals surface through the front door — nothing depends on hallway luck.

R

Root cause

Ask why before fixing what. The problem behind the symptom.

I

Improve

Execute in Jira with a named owner and a visible state.

P

Prove

Evidence lands in SharePoint — runbooks, before/after, numbers.

S

Share

Learning becomes reusable. The loop feeds the next detection.

INTAKE People & teams → Teams front door → categorized & routed
EXECUTE Decision logic → Jira work items → named ownership → visible status
PROVE SharePoint evidence → runbooks → metrics → reusable learning

No new meetings were created in the making of this operating model.
